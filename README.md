# 用户状态记录 · SillyTavern 扩展

一个独立的用户状态记录器：自动从当前聊天整理用户的余额、灵石、积分、境界、任务与进度、物品、丹药、功法、随身用品和名下资产。

## 用链接安装

需要 SillyTavern **1.19.0 或更新版本**，以及可用的“聊天补全”模型连接。

1. 打开酒馆 → 扩展程序 → 安装扩展。
2. 粘贴仓库地址：`https://github.com/xiaochenchen1111/sillytavern-player-state-tracker`。
3. 安装后刷新酒馆，点击右下角“录”字按钮。
4. 打开聊天后默认自动读取；首次会分批整理全部现存消息，顶部显示实际进度。

使用这个扩展时，建议停用此前的“天命系统”脚本，避免重复的模型分析请求。

## 只记录用户的东西

- 收到、明确持有、完成购买的物品加入用户列表；其他角色/NPC的同名物品不会加入或覆盖。
- 送出、出售、消耗、丢失或完全转让后，从当前持有列表移除；部分送出只扣除相应数量。
- 公司或股权部分转让后保留用户剩余归属，完全转让才移除。
- 只浏览的商品、报价、尚未实际支付的意向不视为已拥有。
- 赠送功法的实体副本，不代表用户忘记已经学会的功法；实体物品和修炼能力按剧情分别处理。
- 丹药与物品/道具分类；功法独立；手机、手表、房产、车辆、公司等在资产分类里。
- 详情包含数量、品阶、功能、效果、副作用、使用/修炼要求。剧情没有说明的字段显示“未说明”，未记录的余额显示“未记录”。

## 自动同步与断点

读取酒馆原生完整聊天数组，包含隐藏消息；按当前选择的回复页整理，不依赖手机上显示了多少条聊天。

新增、编辑、删除、重新生成或切换回复页时自动校准。每项结果保留来源；删除一条赠送消息后，如剩余剧情仍支持原来的持有状态，物品会恢复。编辑较早消息后，依赖旧剧情的后续结果会重新分析。

每批完成后保存到当前聊天的 `chatMetadata.playerStateTracker`，不同聊天分开。暂停、继续、重启请求不清除已完成的断点；超时或失败会明确显示，最多自动重试两次。没有读到消息、没有提取到状态、没有合法JSON都不会误报全部同步完成。

## 模型和数据

使用酒馆当前“聊天补全”连接，通过原生独立流式请求获取完整JSON。单次请求上限8192 Token，不会永久修改续写的回复上限。扩展本身不提供模型或API额度，自动提取会产生当前模型的调用费用。

扩展只提供状态记录和核对所需的功能。界面有用户、任务、物品、功法和资产五栏，右上角是自动读取开关、同步进度、诊断和备份。

本地保存的来源缓存用于删除/编辑回退。赠送事件只保留扣减所需操作，不建立收礼人的资产表。仓库只包含扩展代码、测试和说明，不包含用户聊天、存档或API密钥。

AI对归属、数量或模糊剧情的提取仍可能出错，可查看原文并手动修订。导入普通快照属于用户提供的起始资料，不会随删除聊天自动消失；可通过“按当前聊天重新记录”完全重建。

## 开发与测试

无需安装npm依赖。使用Node.js 22或更新版本：

```sh
npm test
```

覆盖用户/NPC归属、赠送和消耗扣除、消息删改回退、断点续读、流式响应、独立响应上限、空结果、切换聊天等。
